0.6.6 CHANGES AND CHECKED BOUNDARIES
- Same-size home publication: two IDs with [64x64,64x64,128x64] render twice,
  formerly six times. Bitmap identity is shared, click identities stay per ID.
  Legacy identical orientations/IDs reuse one render; cache does not survive
  a publication. Retained: max four variants per ID and cache freshness lock.
- No-op style saves: normalized feedback settings are included in equality.
  Disabled feedback and cleanup after expiry skip redundant publication.
  Equal home/floating deadlines share one timer/publication; partial host
  failure, late bitmap arrival after expiry, and cleared-generation races
  still clear potential visible badges without starting another request.
- Floating: automatic-setting/position writes and drag do not allocate a new
  bitmap; changed dimensions do. Unexpired host retries reuse pixels, while
  cache expiry/clock rollback force redraw. Hidden overlays cancel display
  timers; wake restores local expiry without changing network scheduling.
- A background publication during drawing was reproduced: two assertions
  failed before the dedicated main-thread invalidation fix. Five coalesced
  invalidations now produce one follow-up draw containing the latest cache.
- Main uses lifecycle-owned event/preference observers instead of 500 ms
  polling, with label-only updates for usage and local reset/age expiry.
  English errors are localized before display and duplicate suppression.
- Editor lazily creates pages/rows/color wheels; per-frame reflection visits
  visible controls only; no-change flushes are skipped. Source contracts and
  independent review cover this wiring; actual Android interaction is NOT run.
- One serial Repo refresh reads the authoritative encrypted-session double
  once. Cold recovery, changed sessions, after-recovery disable, cancellation,
  token rotation, storage failure, quarantine and 401 retry remain covered.
  No plaintext session map is retained between tasks. Eligibility is checked
  once after recovery, not at each network cancellation checkpoint.

RETAINED SECURITY AND BEHAVIOR LIMITS
The app uses an unofficial browser authentication implementation and internal usage
endpoint. Tokens are not restricted to read-only usage. Passing a build, signature,
local test or emulator test is not proof that connecting an account is safe.
No passwords, account tokens, authorization callback data, signing keys or raw
private-path build logs belong in the distribution.

Automatic refresh uses one JobScheduler interval shared by home and active floating
sessions, 15..10080 minutes with 15/30/60 shortcuts. Saving an interval does not
fetch usage. Scheduled work is not an exact deadline. Device-wide power saving,
background-data restrictions, force-stop and process death can delay or prevent it.
Local diagnostics do not prove the user's S25 Ultra issue is fixed.

The seven manifest permissions remain INTERNET, ACCESS_NETWORK_STATE,
RECEIVE_BOOT_COMPLETED, FOREGROUND_SERVICE, FOREGROUND_SERVICE_DATA_SYNC,
SYSTEM_ALERT_WINDOW and FOREGROUND_SERVICE_SPECIAL_USE. Optional floating display
requires user permission and keeps its own foreground service. No exact alarm,
accessibility service, notification access or separate polling is added.
A floating window shows only saved app usage and does not inspect other apps.
It hides for screen-off/lock, does not automatically return after process death
or reboot, and can be closed by long press, app control or service notification.

Manual refresh uses a bounded foreground helper, cooperative cancellation and
serialized token rotation. A 55-second watchdog / 70-second service cap is not a
strict end-to-end HTTPS response deadline. Success feedback requires new valid
saved data; a tap/error does not rewrite the last successful timestamp.
Home/floating feedback durations are independent. Publication means delivery to
Android, not proof that a physical launcher painted new pixels.
