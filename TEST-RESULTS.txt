0.6.0 floating-widget checks:
The preference tests compare every appearance field across roundtrips, all legacy
format/size/alignment combinations, malformed/oversized/wrong-type storage, default
values, size read/save bounds, and independent returned style objects. Floating
style saves/resets do not overwrite home appearance, credentials, usage, position,
or the floating session's other settings. The old home migration is preserved.

Pure geometry covers portrait/landscape bounds, density-scaled requested sizes,
oversized/invalid dimensions, saved fractions and drag limits. Pure gesture checks
cover tap, movement slop, drag-return, cancellation, duplicate release, and the
600ms long-press state. These do not verify real touch delivery or timing.
Service source assertions inspect overlay type/flags, permission and revocation
checks, specialUse foreground lifetime, screen-lock hiding, local cache reads,
separate style/feedback, explicit settings/close intents, and observer cleanup.
They also distinguish an active session from visible attachment so lock-screen
hiding does not cancel/restart the automatic-refresh interval.

The real manual-refresh service is exercised with Android/Repo/overlay doubles for
the 900ms same-widget triple-tap path, immediate first-tap refresh, suppression of
extra fetches, independent widget IDs, quiet-window reset, and existing completion
ownership. Floating taps remain refresh-only and do not enter the home gesture.
Periodic/feedback checks include floating-only eligibility, session close behavior,
and independent home/floating indicator duration. Publication checks inspect the
per-widget immutable tap intent and floating repaint request in fake-host paths.

Style Activity source review confirms separate mode/title/stores, 48..360dp width,
48..300dp height, default 128x96dp, a pinned aspect-ratio-preserving preview, a resize
shortcut, and all existing appearance controls. Source/model checks do not run real
Android layout, accessibility, keyboard, color-wheel or overlay compositing.

Retained 0.5.2 battery/background guidance and diagnostics:
BackgroundAccess tests exercise API26/27/28/33/34/35/36, power saver and exemption
combinations, API-gated background restriction/pending-job reads, absent jobs/services,
known and future reasons, and independent permission/runtime/linkage failures.
Unavailable status is not labeled unrestricted or unscheduled. An executing reason
and an unavailable read can share a raw number; their display hints remain distinct.
Checks also cover a job disappearing between reads and fresh values on later reads.
Only this package and its periodic job are inspected. The settings intent opens the
generic optimization list, not a direct exemption request.

Added lifecycle/diagnostic checks cover first-use empty records, separate preferences,
current-generation ownership, fixed outcome labels, no secret-shaped arbitrary text,
cache-only publication retries, unsupported/failed platform stop-reason reads, and
storage failure. Old completion/stop/publication callbacks cannot replace newer
diagnostics. Actual query success and publication failure remain distinct; a recorded
OS stop can coexist with a late, known successful query/publication. Diagnostic read
failure is unavailable, not evidence that no job ever ran. Storage failures cannot
block account work, widget publication or normal job completion.

Status records start in 0.5.2 and are best-effort local metadata, not an immutable
event log. Tokens, callback codes, server bodies and raw exception logs are not
diagnostic fields. A missing completion does not prove a job is still running.
Widget delivery means an update reached the Android host interface, not visual
confirmation of the home screen.

MainActivity source review and resource checks confirm the status dialog / Check again
read status without a usage query or resetting a job interval. Settings are chosen by
the user in Android. No Samsung sleeping-list inspection or automatic policy change,
new alarm or extra usage fetch is added by these diagnostics. The separate optional
0.6.0 overlay adds display/specialUse permissions and a session foreground service;
these are not part of the battery-status feature. Existing short browser-login and
manual-refresh foreground services remain.

This is settings guidance and observability, not a verified fundamental fix for
automatic refresh during Samsung power saving. An app optimization exception is not
proof that device-wide background-data restrictions or job quotas are lifted.
The user's specific cause and behavior with each phone setting remain unverified.

The periodic worker now reconciles credentials on Repo.IO, rechecks automatic-refresh
and home-widget/active-floating eligibility, and publishes committed cache before jobFinished.
Tests hold the queue, reconciliation and save/completion boundaries to verify
stop/destroy/replacement behavior, cancelled queued work, signed-out or unreadable
sessions, auto-off/widgets-removed races, completion ownership and executor rejection.
No Activity, real account or real usage HTTP request exists in the lifecycle harness.
A publication failure permits one cache-only retry; late retries read current data
and cannot finish a newer job. No extra usage fetch is introduced for repaint retry.

These 339 checks use captured fake payloads, not real Android RemoteViews/Canvas.

Automatic refresh remains JobScheduler-based at 15/30/60-minute settings. The
manifest now declares seven permissions: the existing INTERNET,
