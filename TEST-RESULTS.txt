RETAINED SECURITY AND BEHAVIOR LIMITS
The app uses an unofficial browser authentication implementation and internal usage
endpoint. Tokens are not restricted to read-only usage. Passing a build, signature,
local test or emulator test is not proof that connecting an account is safe.
No passwords, account tokens, authorization callback data, signing keys or raw
private-path build logs belong in the distribution.

Automatic refresh uses one JobScheduler interval shared by home and active floating
sessions, 15..10080 minutes with 15/30/60 shortcuts. Saving an interval does not
fetch usage. Scheduled work is not an exact deadline. Device-wide power saving,
background-data restrictions, force-stop and process death can delay or prevent it.
Local diagnostics do not prove the user's S25 Ultra issue is fixed.

The seven manifest permissions remain INTERNET, ACCESS_NETWORK_STATE,
RECEIVE_BOOT_COMPLETED, FOREGROUND_SERVICE, FOREGROUND_SERVICE_DATA_SYNC,
SYSTEM_ALERT_WINDOW and FOREGROUND_SERVICE_SPECIAL_USE. Optional floating display
requires user permission and keeps its own foreground service. No exact alarm,
accessibility service, notification access or separate polling is added.
A floating window shows only saved app usage and does not inspect other apps.
It hides for screen-off/lock, does not automatically return after process death
or reboot, and can be closed by long press, app control or service notification.

Manual refresh uses a bounded foreground helper, cooperative cancellation and
serialized token rotation. A 55-second watchdog / 70-second service cap is not a
strict end-to-end HTTPS response deadline. Success feedback requires new valid
saved data; a tap/error does not rewrite the last successful timestamp.
Home/floating feedback durations are independent. Publication means delivery to
Android, not proof that a physical launcher painted new pixels.
